# Логика приложения ТрансКом Аналитика — своими словами

## Что делает приложение в двух словах
Каждый день приложение идёт в Planfix, находит все сделки, с которыми сегодня работали менеджеры, собирает по ним всё (звонки, комментарии, транскрибации), отдаёт ИИ на оценку работы менеджера, и выдаёт красивый HTML-отчёт — для менеджера и для руководителя. Плюс автоматически пишет рекомендации в саму сделку в Planfix.

---

## Шаг 1. Откуда взять сделки за день

В Planfix есть справочник "Реестр активности" — туда автоматически пишется, кто из менеджеров с какой сделкой сегодня что-то делал. Приложение идёт туда, фильтрует по дате и сотруднику — получает список ID сделок, с которыми сегодня работал, например, Ия Боровая.

**Важно:** только эти сделки мы и трогаем. Все остальные — не наши за этот день, никаких API-запросов и никакого Whisper по ним.

---

## Шаг 2. Собрать всё по каждой сделке

По каждой сделке из списка приложение собирает **всю её историю**, не только за сегодня:
- Комментарии самой сделки
- Комментарии её подзадач (если есть)
- Комментарии контрагента (клиента) — все звонки всех сотрудников, не только нашего менеджера. Логика: если директор сам позвонил клиенту — об этом должен знать и менеджер, и РОП.

**Правило кэша (святое):** сначала смотрим в `deal_history.json`. Что там уже лежит — не перекачиваем. Из Planfix тянем только новые комментарии (по ID). После загрузки — сразу пишем в `deal_history.json`. Эта история копится годами.

---

## Шаг 3. Разобрать комментарии на звонки и заметки

Приложение проходит по всем комментариям и раскладывает:
- **Исходящий звонок** / **входящий звонок** — если текст начинается с этих слов или есть mp3
- **НДЗ** (не дозвонились)
- **Заметка** — всё остальное
- **ИИ-комментарии** (которые мы же сами отправили) — отфильтровываются, чтобы не зациклиться

---

## Шаг 4. Транскрибировать звонки

Для каждого звонка надо получить текст разговора:

1. Сначала смотрим внутри самого комментария — Planfix иногда сам вставляет расшифровку после `----------`
2. Фильтруем мусор: если там "закончились AI-кредиты" и подобное — выбрасываем, это не расшифровка
3. Смотрим в `ai_cache.json` по ключу `whisper_{hash}` — вдруг мы этот файл уже транскрибировали раньше
4. Только если нигде нет — скачиваем mp3 и отдаём в OpenAI Whisper, результат сохраняем в кэш

**Лимит:** не больше 70 транскрибаций за один запуск, чтобы не разорить аккаунт.

---

## Шаг 5. Оценить работу менеджера через ИИ

Теперь по каждой сделке есть полная картина: кто звонил, что говорил, что писал. Отдаём это в DeepSeek (или fallback Polza.ai) с подробным промптом:

ИИ оценивает по 7 критериям скрипта продаж (максимум 12 баллов):
- Приветствие
- Выявление потребностей
- Устная презентация (критерии разные для снега и асфальта)
- Работа с возражениями
- Закрытие

И возвращает:
- **Общий вердикт** (хорошо/плохо/что не так)
- **Баллы ЗП** (из 12) — это потом пойдёт в расчёт зарплаты менеджера
- **Рекомендации** — что менеджер сделал не так
- **Следующий шаг** — конкретное действие по этой сделке
- **Соль по сделке** — 1-2 предложения, что сейчас происходит

**Три слоя валидации:** до ИИ программа готовит данные, после ИИ программа проверяет результат (например, что `source="call"` указан только когда слова реально есть в транскрибации).

**Кэш оценок:** если оценка за эту дату уже есть в `deal_history.json` → `assessments` — не пересчитываем. Ключ `assess_{dealId}_{date}_v20` (снег) или `v20a` (асфальт).

---

## Шаг 6. Red-флаги (без ИИ, программно)

Параллельно программа сама проверяет сигналы опасности:
- **Не обработана >30 мин** — сделка в статусе "Новая" висит больше получаса
- **Нет КП >24ч** — в статусе Обработка/КП, а файла КП нет
- **Забыта** — никто (не робот) не трогал сделку 10+ дней
- **Высокий приоритет** — сумма >1 млн ₽

---

## Шаг 7. Догенерация оценок за прошлые дни

Отчёт показывает не только сегодня, а последние 30 дней (вкладка "Ежедневные"). Программа проходит по истории и для каждой сделки смотрит: есть ли оценка за тот день? Если нет — генерирует прямо сейчас. Это чтобы даже если за какой-то день отчёт не запускался — оценки всё равно появились.

Есть предохранитель по таймауту (`isTimeUp()`), чтобы не зациклиться.

---

## Шаг 8. ИИ-итог дня + отчёт руководителя

Отдельный запрос к DeepSeek: отдаём агрегированные данные дня (red-флаги, краткие описания сделок) и просим сформировать:
- Итог дня менеджера
- Отчёт руководителя за день / неделю / месяц
- Категории: срочно дожать, забытые, нет документов, хорошо идут, деньги, план действий

---

## Шаг 9. Собрать HTML-отчёт

9 вкладок, каждая отдельный файл в `src/report/tabs/`:
1. **День** — карточки сделок за сегодня с ИИ-оценкой и next step
2. **Все сделки** — полный список с фильтрами
3. **Качество** — анализ звонков
4. **Ежедневные** — сравнение дней
5. **Воронка** — визуализация
6. **Статистика** — графики/тренды
7. **Входящие** — входящие обращения
8. **Руководитель** — AI-выжимка для РОПа
9. **Замеры** — анализ замеров

HTML получается **self-contained** (один файл, всё внутри — CSS, JS, данные). Серверная часть вкладки (`имя.js`) читает клиентскую (`имя.client.js`) и оборачивает её в `<script>`.

---

## Шаг 10. Автоотправка рекомендаций в Planfix

Для сделок, где ИИ нашёл косяки (`missing.length > 0`), программа автоматически пишет комментарий прямо в сделку: "ИИ-оценка: X/12 баллов, вот что надо исправить…".

**Защита от спама:** не более 1 отправки в день на сделку. Ключ `sent_{dealId}_{date}` в `ai_cache.json`. Флаг `--no-send` отключает (для тестов).

Зачем: менеджер видит оценку прямо в ленте сделки — это и мотивация, и обучение.

---

## Шаг 11. Коммит и пуш

После генерации — автоматический `git commit` + `git push` в ветки `master` и `main`. GitHub Actions подхватит, GitHub Pages опубликует. Без этого пользователь увидит старый отчёт.

Файлы, которые всегда должны быть актуальны в репо: `deploy/`, `report.html`, `reports/`, `data/`, `ai_cache.json`, `deal_history.json`, `latest_data.json`.

---

## Шаг 12. Верификатор (`verify.js`)

Отдельный скрипт-аудитор. Запускается после отчёта, идёт по каждой сделке в Planfix и сверяет:
- Все ли сделки из реестра попали в отчёт
- Все ли звонки найдены (не потерялись)
- Все ли звонки транскрибированы
- У всех ли есть ИИ-оценка с вердиктом
- Все ли рекомендации отправлены в Planfix
- HTML-файлы существуют и валидны

Результат → Telegram. В CI запускается автоматически.

---

## Что крутится автоматически

**GitHub Actions** каждый день в 19:00 МСК (16:00 UTC):
1. Запускает `analytics.js` для каждого менеджера из `managers.json`
2. Запускает `verify.js --all`
3. Коммитит обновлённые данные
4. Деплоит на GitHub Pages

---

## Ключевая идея, которую легко упустить

**Кэш — не оптимизация, а архитектура.** Если запустить программу повторно за тот же день — она НЕ должна делать ни одного лишнего API-запроса и ни одного вызова Whisper. Всё уже в `deal_history.json` и `ai_cache.json`. Это экономит деньги (Whisper платный), время и защищает от сбоев API. Если кто-то обходит кэш — это баг, не фича.

**deal_history.json — это память приложения.** Она копится годами, ничего не удаляется. История сделки доступна всегда, и для отчёта за сегодня, и для отчёта за месяц назад.
