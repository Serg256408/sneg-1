# Принятые решения и правила (НЕ ОБСУЖДАЮТСЯ)

Перед изменением кода в `src/core/` или `src/api/` — прочитай этот файл.
Если твоё изменение противоречит правилам — СТОП, спроси у пользователя.

## ВЫСШИЙ ПРИОРИТЕТ — ЗАГРУЗКА ДАННЫХ И ТРАНСКРИБАЦИЯ
**Нарушение = баг. НЕ ОБСУЖДАЕТСЯ, НЕ ПЕРЕСПРАШИВАЕТСЯ, НЕ УПРОЩАЕТСЯ.**

1. Работаем ТОЛЬКО со сделками менеджера за день отчёта (из реестра активности)
2. Для каждой такой сделки загружаем ВСЕ комментарии (за всё время) — из кэша `deal_history.json`. Если в кэше нет — из API, и СРАЗУ сохраняем в кэш
3. То же самое для подзадач этих сделок и контрагентов этих сделок
4. Если в комментариях есть звонок с mp3 — проверяем кэш `ai_cache.json`. Есть транскрибация → берём. Нет → Whisper → сохраняем в кэш
5. Сделки которые НЕ в реестре за этот день — НЕ ТРОГАЕМ. Никаких API-запросов, никакого Whisper
6. При повторном запуске за тот же день — ВСЁ из кэша, ноль лишних запросов к API и Whisper

**ПОРЯДОК: кэш → API (если нет в кэше) → сохранить в кэш. ВСЕГДА.**

## Planfix API

- Домен: `transkom.planfix.ru` (НЕ `.com`)
- Токен: из `.env` → `PLANFIX_TOKEN`
- Все запросы через `pf()` из `src/api/planfix.js`
- Формат даты: `DD-MM-YYYY`
- Пагинация: `pageSize: 100`, цикл по `offset`
- API справочников НЕ поддерживает фильтры по полям — фильтрация в коде
- ID шаблонов: Сделка = 121, Вывоз снега = 14090
- ID статусов: Обработка=120, КП=110, Клиент решает=111, Договор=112, Отложенная=4, Завершена=114, Замер=134

## Источник сделок

- Сделки менеджера за день берутся из справочника "Реестр активности" (directory 16572)
- Поля: Дата=34134, Сотрудник=34136, Id Задачи=34138, Название=34140
- Фильтрация по дате и сотруднику — в коде (API не поддерживает)
- Ранний выход: если вся страница записей — не за нашу дату, выходим

## Кэширование данных (ЖЕЛЕЗНОЕ ПРАВИЛО)

- Все данные сделок хранятся в `deal_history.json` (комментарии, транскрибации, ИИ-оценки)
- При загрузке: СНАЧАЛА `deal_history.json`, из API только новые (по id комментария)
- Whisper транскрибации в `ai_cache.json` (ключи `whisper_*`) — повторно НЕ вызывать
- ИИ-оценки в `deal_history.json` → `assessments` — не пересчитывать если есть
- После загрузки из API — ВСЕГДА сохранять в `deal_history.json`
- Отчёт ВСЕГДА включает прошлые дни (до 30) из `deal_history.json` через `multiDayActivity`
- Вкладка "Ежедневные" показывает ВСЕ ранее обработанные дни, не только текущий

## Whisper (транскрибация звонков)

- Работает ТОЛЬКО для сделок активных за день отчёта (из реестра активности)
- Для активной сделки: транскрибируем ВСЕ звонки (и старые тоже) — чтобы ИИ видел полную картину
- Для прошлых дней (из истории): только из кэша, НЕ вызывать Whisper
- allowWhisper=true передаётся в parseComment для активных сделок
- Есть mp3 + нет транскрибации в тексте + нет в кэше → вызвать Whisper
- Результат сохраняется в `ai_cache.json` с ключом `whisper_{hash}`
- НЕ транскрибировать звонки из сделок которых нет в реестре за день
- Лимит: 70 транскрибаций за запуск

## Определение звонков

- Комментарий = звонок если:
  - `description` начинается с "Исходящий звонок" или "Входящий звонок"
  - Или содержит паттерн `----------` + символы `🔴🔵●` (транскрибация в тексте)
  - Или в `files` есть mp3 с "Запись звонка"
- Транскрибация ищется СНАЧАЛА в тексте комментария (`extractTranscription`), потом Whisper
- `outCall` — "исходящий звонок", `inCall` — "входящий звонок", `ndz` — "ндз", `note` — остальное

## Комментарии

- Загружаются из 3 источников: сделка, подзадачи, контрагент
- СНАЧАЛА из `deal_history.json`, из API только новые по id
- Контрагент: ищем дубли по нормализованному телефону (8/7/+7 → 10 цифр)
- Исключаем ИИ-комментарии (содержат "ии-оценка", "баллы зп:" и т.д.)
- Дедупликация звонков из контакта: по дате + время ±5 мин

## Red-флаги

- "Не обработана >30 мин" — статус "Новая" больше 30 минут
- "Нет КП >24ч" — статусы Обработка/КП, нет файла КП, НЕ на замере
- "Забыта" — нет активности ЛЮБОГО сотрудника (не робота) >10 дней, статусы: Обработка/КП/Замер/Клиент решает/Договор
- "Высокий приоритет" — сумма >1 000 000 ₽, активная сделка
- Сравнение дат через Date объекты (НЕ строковое сравнение DD-MM-YYYY)
- Определяются программно (detectRedFlags), НЕ ИИ

## ИИ-оценка

- 7 критериев скрипта продаж, макс 12 баллов
- Два типа: снег (isSnow) и асфальт — разные подпункты устной презентации
- 3 слоя валидации: программный предрасп → ИИ → программная пост-валидация
- source="call" ТОЛЬКО если слова есть в транскрибации, НЕ в заметках
- Поле `dealSituation` — краткая соль по сделке (1-2 предложения)
- `nextStep` показывается наверху карточки, не внизу
- Ключ кэша: `assess_{dealId}_{date}_v20` (снег) / `v20a` (асфальт)

## Отчёт руководителя

- Генерируется за 3 периода: день (1), неделя (7), месяц (30)
- Категории: срочно дожать, забытые, нет документов, хорошо идут, деньги, план действий
- В данных передаются red-флаги и dealSituation

## Менеджеры

- Список в `managers.json`: alias, userId, name, pfName
- Для каждого менеджера отдельный отчёт: `reports/{alias}.html`, `data/{alias}_latest.json`
- Добавление нового менеджера — строка в `managers.json`
